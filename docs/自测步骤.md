# kb-rag 自测手册（M1+M2 · 配 Key 模式）

> 前提：`../kb-rag-deploy/.env` 已填 `DASHSCOPE_API_KEY`（已确认）；中间件容器在跑（已确认）。
> 端口：server **20000** / parser **20001** / web **20002**。管理员：`admin` / `admin`（2026-07-25 按你要求改为 admin，直接改库绕过 API 的 8 位校验；该校验本身保留）。

## 一、启动服务（三个终端，或依次后台）

```bash
# 0.（仅当容器没在跑时才需要）启动中间件
cd /AI/kb-rag/kb-rag-deploy && docker compose -f docker-compose.lite.yml up -d
```

```bash
# 1. 启动解析服务 parser（终端 A）
cd /AI/kb-rag/kb-rag-parser && .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 20001
```

```bash
# 2. 启动主服务 server（终端 B）——关键：加载 .env 里的 Key
cd /AI/kb-rag/kb-rag-deploy && set -a && source .env && set +a && \
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.0.1.jdk/Contents/Home && \
$JAVA_HOME/bin/java -jar ../kb-rag-server/kb-api/target/kb-rag-server.jar
```

```bash
# 3. 启动前端 web（终端 C）
cd /AI/kb-rag/kb-rag-web && npm run dev
```

启动就绪判定：
```bash
curl -s http://127.0.0.1:20000/actuator/health | head -c 60   # 期望 {"status":"UP"...
```
浏览器打开 **http://localhost:20002** → 登录。

## 二、自测前检查（系统设置页）

进入「系统设置 → 模型状态」：**embedding / rerank / chat 三张卡应全部显示已配置**，各点一次"测试连接"应通过。
（若某卡未配置：检查 .env 是否缺 `RERANK_MODEL` / `CHAT_MODEL`——默认 gte-rerank / qwen-plus，通常无需额外配置。）

## 三、自测场景清单

### A. 基础链路（M1 配 Key 验收）
1. 新建知识库 → 上传一个 pdf/docx →文档列表状态几秒内走到「已就绪」
2. 打开分片抽屉：分片可见，embedding 状态应为 **DONE**（不再是零 Key 时的 SKIPPED）
3. 检索调试页：输入与文档内容相关的问题 → 应返回结果，结果卡片能看到**向量分和 BM25 分同时存在**（双路都工作了），顶部无 degraded 警示

### B. 调参对比（M2 验收 1）
同一个 query 反复检索，逐项改参数观察分数变化：
- 融合模式 rrf ↔ weighted，weighted 下拖动 w_vec 滑杆 → 排序应随权重变化
- 重排开关开 ↔ 关 → 开启时结果卡片出现 **rerank 分**、score_type 显示 rerank；关闭时变 fused_*
- 阈值 score_threshold 设 0.5 → 低分结果被过滤，applied 信息条显示阈值作用在哪种分上
- 改写开关打开 → applied 信息条显示**改写后的 query**（试试口语化问题，如"那个降级的事儿怎么搞的"）

### C. 父子分片（M2 验收 5 的一部分）
1. 知识库详情 → 索引配置：开启父子分片（父 1200 / 子 400）→ 保存
2. 出现「N 篇文档使用旧配置」提示条 → 点「按新配置重建」→ 提示条消失
3. 再检索：结果卡片内容变长（父片），展开可见**命中子片明细**

### D. ik 词典（M2 验收 3，可选——需构建 ik 镜像）
不构建 ik 镜像时跳过（当前 ES 用 standard 分词）。要测的话：
```bash
cd /AI/kb-rag/kb-rag-deploy && \
docker compose -f docker-compose.lite.yml -f docker-compose.es-ik.yml up -d --build
```
然后：系统设置 → ik 词典 → 加一个文档里的专有词（如产品代号）→ 约 1 分钟后（ik 轮询词典）重建该库 → 用该词检索，BM25 命中应改善。

### E. 聊天记录过滤（metadata_filter，界面路径）
检索调试页 → 过滤组：填会话 ID / 发送人 / 时间范围。若库里没有聊天数据（未走过 M3/M8 聊天导入），**预期填任意会话 ID 返回 0 条**——证明过滤在引擎侧真实生效。

### F. 文档批量操作
1. 知识库详情 → 文档管理：勾选两三个文档 → 表格上方出现「已选中 N 个文档」操作条
2. 表头复选框全选本页；点表头复选框旁的下拉 → **全选 / 反选 / 清空** 三项都应生效
3. 点「批量重建」→ 确认 → 提示「已提交 N 个重建任务」，被选中的行状态回到处理中
4. 勾选后点「批量删除」→ 确认 → 提示「已将 N 个文档移入回收站」，「回收站」标签页能看到并还原
5. 翻页 → 勾选自动清空（批量操作只作用于当前页，避免删掉翻走后看不见的文档）
6. 若一篇文档在勾选后被另一个窗口删掉，再提交批量删除 → 提示会写明「M 个已在回收站中，已跳过」，其余照常删除

### G. 压测（M2 验收 6，命令行）
```bash
cd /AI/kb-rag/kb-rag-deploy && \
TOKEN=$(curl -s -X POST http://127.0.0.1:20000/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin"}' | python3 -c "import json,sys;print(json.load(sys.stdin)['data']['token'])") && \
KB_ID=<你的知识库ID，界面地址栏可见> BASE_URL=http://127.0.0.1:20000 TOKEN=$TOKEN ./scripts/benchmark.sh
```
验收线：基础链路 P95 < 2s（rerank 开、改写关）；完整链路（改写开）P95 < 3s。

## 四、常见问题
- server 启动即失败提 Qdrant → .env 的 `QDRANT_URI` 必须为空（lite 模式）
- 上传后卡「解析中」→ 确认 parser（20001）在跑：`curl http://127.0.0.1:20001/health`
- 登录 5 次失败会锁 15 分钟（防爆破按设计工作）
- 密码忘了 → 清库重来：`docker compose -f docker-compose.lite.yml down -v` 后重启 server，新随机密码在 server 启动日志里
