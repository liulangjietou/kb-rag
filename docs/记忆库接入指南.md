# 记忆库开放 API 接入指南（Memory Key 调用方式）

> 面向对象：需要为最终用户维护长期记忆的外部智能体应用（Agent / 机器人 / 工作流）。
> 对标产品：阿里云百炼「记忆库」，接口语义与其 AddMemory / SearchMemory / ListMemory / UpdateMemory / DeleteMemory 一一对应。

## 1. 一分钟总览

1. 管理员在控制台「记忆库」菜单创建一个记忆库（自动内置「默认项目」记忆片段规则，开箱即用）。
2. 在该记忆库详情页的「Memory Key」Tab 签发一个 Key，得到形如 `kb-mk-…` 的明文（**仅展示一次**）。
3. 智能体侧每次请求携带请求头 `Authorization: Bearer kb-mk-…` 调用 `/api/v1/memory/**`。
4. 一个 Memory Key 只绑定一个记忆库：请求无需也无法指定 library_id，数据天然按应用隔离。
5. 用不同的 `user_id` 区分你的最终用户（记忆实体），同一 Key 下不同 `user_id` 的记忆互不可见。

## 2. 鉴权与限流

| 项目 | 说明 |
| --- | --- |
| 请求头 | `Authorization: Bearer kb-mk-xxxxxxxx…`（缺失或格式错误返回 401 `INVALID_API_KEY`） |
| Key 被禁用 | 返回 401 `API_KEY_DISABLED`（控制台可随时启停） |
| 限流 | 每个 Key 独立令牌桶，QPS 上限在签发时设定；超限返回 429 `RATE_LIMITED`，建议指数退避重试 |
| 轮换 | 控制台轮换后旧密钥**立即失效**，无宽限期，请配合配置中心热更新 |

所有响应为统一信封：

```json
{ "code": "OK", "message": "success", "data": { ... }, "request_id": "…" }
```

`code != "OK"` 即业务失败，排障时请携带 `request_id`。

## 3. 接口一览

Base URL：`http(s)://<你的部署地址>/api/v1/memory`

| 能力 | 方法与路径 | 说明 |
| --- | --- | --- |
| AddMemory | `POST /add` | 从对话抽取记忆，和/或直写一条记忆 |
| SearchMemory | `POST /search` | 语义召回记忆节点 + 用户画像 |
| ListMemory | `GET /memory_nodes` | 分页列出某实体的记忆节点 |
| UpdateMemory | `PATCH /memory_nodes/{nodeId}` | 替换某节点内容 |
| DeleteMemory | `DELETE /memory_nodes/{nodeId}` | 删除某节点 |
| GetUserProfile | `GET /profiles` | 读取某实体的用户画像 |

## 4. 接口详解

### 4.1 AddMemory — 写入记忆

`POST /api/v1/memory/add`

```bash
curl -X POST "$BASE/api/v1/memory/add" \
  -H "Authorization: Bearer $MEMORY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "u_1001",
    "messages": [
      {"role": "user", "content": "我叫张三，平时只喝无糖拿铁"},
      {"role": "assistant", "content": "好的，已记住您的口味偏好"}
    ],
    "custom_content": "会员等级：黄金",
    "fragment_rule_id": null,
    "profile_rule_id": null,
    "meta_data": {"channel": "app"}
  }'
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `user_id` | 是 | 记忆实体标识，即你的最终用户 ID |
| `messages` | 二选一 | 对话片段（`role` + `content`），由 LLM 按片段规则抽取记忆；配置了画像规则时同步抽取画像 |
| `custom_content` | 二选一 | 跳过抽取，把该文本原样写成一条记忆（`source=CUSTOM`）；与 `messages` 可同时提供 |
| `fragment_rule_id` | 否 | 指定记忆片段规则；不传用内置「默认项目」规则 |
| `profile_rule_id` | 否 | 指定画像规则；不传则遍历库内全部画像规则 |
| `meta_data` | 否 | 业务自定义 JSON，原样存取 |

响应 `data`：

```json
{
  "memory_nodes": [
    {"memory_node_id": "mnode_xxx", "content": "用户只喝无糖拿铁", "event": "ADD"}
  ],
  "profile": {
    "rule_id": "mpr_xxx", "rule_name": "基础画像", "user_id": "u_1001",
    "attributes": [{"name": "称呼", "value": "张三"}], "updated_at": "2026-07-31 10:00:00"
  }
}
```

`event` 取值 `ADD`（新增）或 `UPDATE`（规则开启 auto_update 时语义重复的旧记忆被覆盖）。抽取不到有效记忆时 `memory_nodes` 为空数组，属正常情况。

### 4.2 SearchMemory — 检索记忆

`POST /api/v1/memory/search`

```bash
curl -X POST "$BASE/api/v1/memory/search" \
  -H "Authorization: Bearer $MEMORY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "u_1001",
    "query": "用户喜欢喝什么？",
    "max_results": 5,
    "intent_recognition": true,
    "rewrite": true,
    "rerank": true,
    "similarity_threshold": 0.3
  }'
```

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `user_id` | 是 | - | 记忆实体标识 |
| `query` | 是 | - | 检索语句 |
| `fragment_rule_id` | 否 | 不限 | 只在某条片段规则下召回 |
| `max_results` | 否 | 10 | 1-100 |
| `intent_recognition` | 否 | false | 开启后先判别该查询是否需要召回记忆，无需时直接返回空（省一次向量检索） |
| `rewrite` | 否 | false | 开启后先将口语化查询改写为检索友好表述 |
| `rerank` | 否 | false | 开启后对召回结果做重排序 |
| `similarity_threshold` | 否 | 不过滤 | 0-1，低于阈值的结果被丢弃 |

响应 `data`：

```json
{
  "memory_nodes": [
    {"memory_node_id": "mnode_xxx", "user_id": "u_1001", "content": "用户只喝无糖拿铁",
     "source": "EXTRACTED", "score": 0.87, "meta_data": {"channel": "app"},
     "expire_at": "2027-01-27 10:00:00", "created_at": "…", "updated_at": "…"}
  ],
  "profiles": [ { "rule_id": "…", "attributes": [ … ] } ],
  "rewritten_query": "用户的饮品口味偏好",
  "intent_recalled": true
}
```

已过期的记忆不会被召回。建议把 `memory_nodes[].content` 与 `profiles` 拼进系统提示词后再回答用户。

### 4.3 ListMemory — 分页列出记忆

`GET /api/v1/memory/memory_nodes?user_id=u_1001&rule_id=&page_num=1&page_size=10`

响应 `data`：`{"memory_nodes": [ … ], "page": 1, "size": 10, "total": 42}`（按更新时间倒序）。

### 4.4 UpdateMemory — 更新记忆

`PATCH /api/v1/memory/memory_nodes/{memory_node_id}`

```bash
curl -X PATCH "$BASE/api/v1/memory/memory_nodes/mnode_xxx" \
  -H "Authorization: Bearer $MEMORY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"user_id": "u_1001", "custom_content": "用户现在改喝燕麦拿铁", "meta_data": {"channel": "app"}}'
```

`user_id` 与 `custom_content` 必填；节点不属于该 `user_id` 或不属于本 Key 绑定的记忆库时返回 404。

### 4.5 DeleteMemory — 删除记忆

`DELETE /api/v1/memory/memory_nodes/{memory_node_id}?user_id=u_1001`

成功返回 `{"code": "OK", "data": null}`。

### 4.6 GetUserProfile — 读取用户画像

`GET /api/v1/memory/profiles?user_id=u_1001&rule_id=`

响应 `data` 是数组，每条画像规则一项；尚未抽取到的字段回落到规则里配置的 `initial_value`（无初始值则为 `null`）。

## 5. 典型接入模式（伪代码）

```python
def chat(user_id: str, user_message: str) -> str:
    # 1. 先召回记忆，拼装上下文
    recall = post("/api/v1/memory/search", {
        "user_id": user_id, "query": user_message,
        "max_results": 5, "intent_recognition": True, "rewrite": True, "rerank": True,
    })
    memory_context = "\n".join(n["content"] for n in recall["memory_nodes"])

    # 2. 带着记忆调用你自己的 LLM
    answer = llm(system=f"已知该用户的长期记忆：\n{memory_context}", user=user_message)

    # 3. 会话结束后异步写回本轮对话，抽取新记忆（不要阻塞回复）
    post_async("/api/v1/memory/add", {
        "user_id": user_id,
        "messages": [
            {"role": "user", "content": user_message},
            {"role": "assistant", "content": answer},
        ],
    })
    return answer
```

## 6. 错误码速查

| HTTP | code | 含义与处理 |
| --- | --- | --- |
| 400 | `INVALID_PARAM` | 参数错误，`message` 为中文说明，修正后重试 |
| 401 | `INVALID_API_KEY` | Key 缺失/格式错/已轮换，检查配置 |
| 401 | `API_KEY_DISABLED` | Key 被禁用，联系管理员启用 |
| 404 | `NOT_FOUND` | 资源不存在或不属于你（跨库/跨实体访问一律 404，不是 403） |
| 429 | `RATE_LIMITED` | 超过 Key 的 QPS 限额，指数退避后重试 |
| 500 | `INTERNAL_ERROR` | 服务端异常，携带 `request_id` 排障 |

## 7. 最佳实践

- **user_id 规划**：用你系统里稳定且不含个人敏感信息的用户主键（如内部 UID），不要用手机号明文。
- **写入时机**：一轮或一段会话结束后再调用 AddMemory，异步执行；LLM 抽取有秒级耗时，不要放在回复主链路上。
- **检索开关**：高频调用场景建议开启 `intent_recognition`，闲聊类查询会被判定为无需召回，直接省掉检索开销。
- **过期策略**：片段规则的过期时间（7/30/180 天/永不）决定记忆生命周期；已过期节点不参与召回，但控制台仍可见。
- **Key 管理**：一个下游应用一个 Key，便于独立限流、独立禁用与审计；密钥仅签发时展示一次，请存入密钥管理系统。
- **多应用隔离**：不同智能体应用如需完全隔离的记忆，请分别建库、各发各的 Key；同库多 Key 则共享记忆数据。
