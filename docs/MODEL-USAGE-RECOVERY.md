# 超时预占的状态与事务

进程可能在模型提供方接受请求后中断，服务无法再得到准确用量。后台继续按既有预占上界保守结算，将预占转入估算用量；不能直接释放为零消耗。

## 行为修正

`ModelUsageService.reconcileStaleReservations` 对超时仍处于 `RESERVED` 的记录写入 `FAILED` 和错误分类 `RESERVATION_EXPIRED`，保留 `estimated=1`。这表示本地调用未正常完成结算，不等于已经确认提供方没有生成结果。正常完成但未提供准确计数的调用仍可为 `SUCCEEDED`，两种情况不再混淆。

每笔账本仍通过乐观锁领取，再更新对应租户月份的计数。当前批次中任何计数更新失败都会抛出异常，让 Spring 回滚整个批次，避免账本已结束而预占未转换。异常留存错误码与用量标识；修复异常原因后，下次定时执行可重试。

不改变预占上限、价格快照、超时时长和定时频率，不新增数据库迁移。已有历史记录缺少明确的过期标记时，不推断改写其状态。

## 验证

`ModelUsageRecoveryTransactionTest` 使用生产迁移表结构、Mapper、乐观锁和 Spring 事务，覆盖整批回滚、重复执行不重复扣量、租户分别结算、未超时与软删除记录保持原样。默认使用 H2 MySQL 模式，也可设置 `KB_USAGE_TEST_JDBC_URL` 指向专用 `codex_usage_` 测试库，在真实 MySQL 上执行；不得指向业务库。

定时任务中的事务修正不影响正常调用的同步结算。回退服务端二进制无需回迁数据，但旧版本的超时回收会恢复原有错误终态和异常处理行为。
