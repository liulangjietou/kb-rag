# 应用版本差异

在应用的“版本与发布”中打开“版本差异”，先选择对照版本，再核对目标版本的配置与资料。比较只读取数据，不保存配置、发布版本、冻结索引或启动评测。

## 配置

每次打开或刷新重新读取版本列表。比较关联知识库及权重、检索参数、模型、提示词、路由、门禁参数与门禁评测集绑定。对象属性顺序不产生差异；知识库顺序保留，因为首个知识库可能提供默认配置。零值、关闭、空文本与未设置分别显示。配置使用既有版本接口的兼容投影，草稿在提交测试时尚可能补全默认值。

## 资料

`GET /api/v1/app-versions/{id}/corpus-diff?baseline_id={id}&page=1&page_size=20`，省略 `baseline_id` 表示明确的空基线。分页从 1 开始，每页最多 100 条。

- `FROZEN`：该应用版本保存的发布资料集合；显式空列表是合法空集合。
- `CURRENT`：未发布版本引用知识库的当前活动集合，复用检索链路的活动版本缓存，尚未冻结。
- `EMPTY`：用户选择无对照。
- `UNAVAILABLE`：历史集合缺失，不能以当前集合补写历史。

需要 `app:read`、`kb:read`、当前应用数据范围和两侧全部知识库范围。版本租户及同应用归属先校验；当前文档 ACL 在差异统计和分页之前裁剪。物理查询再次约束版本、文档、知识库及租户，按 500 个版本 ID 分批读取。响应只含当前文档名称、版本及新增、移除、版本替换标记，不含正文和对象存储地址，禁止缓存。

任一集合或文档版本元数据不完整时，`comparable=false`，数量未知且不返回推断的差异条目。权限不足或接口失败显示可重试错误，不显示“无差异”。当前无权读取的资料不影响数量和分页；本功能不代表无权限差异的全库审计。

资料比较不检查物理索引健康，也不代替发布门禁或真实业务问答验收。门禁“双跑结果”的对照始终表示门禁执行时的正式版，后续发布不会改写该历史身份。
