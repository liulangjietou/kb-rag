# 问答调试耗时诊断

问答调试页每轮回答下可以展开耗时诊断，服务端测量与浏览器接收分别展示。现有主题、主色和用户选择保持不变。

## 测量边界

| 测量 | 起止边界 |
| --- | --- |
| 配置解析 | `KnowledgeApiService.preview` 开始至进入检索，包括版本解析和配置校验 |
| 检索 | 调用现有检索编排至返回并通过取消检查，包括改写、路由、召回、融合、重排等实际启用的步骤 |
| 重排（检索内） | 现有 `RerankService.rerank` 同步调用起止，包含调度、模型等待与分数数量校验；关闭、无候选或模型不可用时不填耗时 |
| 生成 | 开始生成至生成完成，包括模型等待及服务端增量写出，不含最终引用和终态帧写出 |
| 服务端首段等待 | 从预览开始执行到生成器交付第一个非空增量，非流式或没有增量时未采集 |
| 服务端执行总耗时 | 从预览执行开始至成功或异常结束，不含鉴权、异步执行前排队、最终引用/终态写出和网络往返 |
| 浏览器首段等待 | 发起请求前至解析到第一个非空增量；非流式不适用 |
| 浏览器接收总耗时 | 发起请求前至业务终态、失败或用户停止；不包含后续页面绘制 |

服务端使用 `System.nanoTime`，浏览器使用 `performance.now`，都不受墙上时钟调整影响。首段等待包含在总耗时中，重排包含在检索中，都不能重复相加；各段分别取整到毫秒，合计可能有舍入差。改写、路由和召回尚未单独采集，不能从总检索时间推断其各自耗时。

重排的 `rerank_status` 区分 `APPLIED`（已应用）、`DISABLED`（未启用）、`EMPTY_CANDIDATES`（无候选）、`UNAVAILABLE`（模型不可用）、`TIMEOUT`（超时）、`FAILED`（失败）和 `SKIPPED`（未能进一步细分的跳过）。只有已应用、超时和失败携带 `rerank_ms`，小于一毫秒的实际调用可以为 0。线程池拒绝也计为失败，计时不代表模型已经执行。重排超时或失败后沿用现有粗排序，不自动将整轮问答判为失败。

重排测量与同次检索结果一起返回，预览显式取出后投影为诊断；原检索、公开 API、员工会话和评测响应不增加该字段。检索未返回结果快照时，子阶段保持未知，包括在重排之前或之后抛异常的情况，不能据此判断重排是否调用过。生成失败或检索返回后的取消保留已经收到的重排测量。没有新增模型调用、索引写入或后台计时任务。

失败时保留已经测量的阶段，并标明停止于配置、检索还是生成。未执行阶段、缺失诊断与合法的 0 毫秒明确区分。已收到的正文保留，诊断事件不会把失败或缺失终态的回答改为成功。连接已经关闭时，浏览器可能只能报告本地接收用时。

## 接口与权限

只对原有控制台 `/api/v1/apps/{appId}/chat-preview` 编排采集诊断，沿用应用、知识库、租户及文档权限；预览仍使用所选版本配置和当前语料。正常 JSON 成功响应可选 `data.diagnostics`，流式响应在业务终态之前发送可选 `diagnostics` 事件。旧流接收器可忽略扩展事件，`message_delta`、`references`、`done`、`error` 不变。

普通公开 API、MCP 和员工持久会话不会因本功能新增模型调用或诊断记录。共享 JSON 响应对未采集调用省略 `diagnostics`。不增加数据库表、后台任务或索引写入。诊断只包含耗时、阶段、结果与请求标识，不包含提示词、密钥或租户账本。

页面按登录身份、权限和知识库范围隔离状态，切换后取消旧流并移除旧回答；应用/版本切换继续沿用现有请求序号保护。可选诊断损坏时不破坏正文协议。费用使用已有模型用量账本，不能由耗时估算，也不向调试权限额外开放租户费用。

## 验证边界

自动化覆盖可控单调时钟、首个非空增量、检索和生成失败、SSE 扩展与终态、JSON 字段兼容、身份切换及迟到内容、非流式、停止、旧服务缺失诊断、键盘操作和十二套固定主题五宽度。System 的跟随行为另有专门验证。模拟延迟只验证显示语义，不作为真实 P50/P95 或业务 RAG 质量成绩。
