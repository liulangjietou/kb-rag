## 推荐读法

1. **第一遍**：读 03 的「十条原则」和 01 的 Q1–Q6，能用 3 分钟讲清项目与方法论。
2. **第二遍**：精读 01 全文，遇到「详见八股第 N 题」就跳到 [RAG 工程面试八股](../RAG面试八股.md) 对应题目。
3. **第三遍**：刷 02，每题答完用「我们在项目里是这样做的」收尾，把理论落回项目。
4. **面试前一天**：看 01 的「踩坑复盘」和「已知缺口」，以及八股文末的参数速查。

## 答题框架

高级岗的评分点是四种意识，每道题都往这四个方向答：

| 意识 | 面试官在问什么 | 答题动作 |
| --- | --- | --- |
| 取舍 | 为什么不是另一种方案？代价是什么？ | 先给结论，再说放弃了什么 |
| 闭环 | 你怎么证明改动是正向的？ | 评测集、门禁、指标 |
| 边界 | 方案在什么情况下失效？ | 主动讲已知缺口和修法 |
| 演进 | 复杂度是什么时候、因为什么引入的？ | 用真实信号解释，而不是「预计未来」 |

答题格式：**先结论后论证**——一句话结论 → 两三条关键理由 → 一个真实的数字或代码位置 → 代价或边界。

## 口径约定

- 「本项目」「kb-rag 落地」指本仓库主干实现，类名可在 `kb-rag-server` 中直接检索。
- 「八股第 N 题」指 [RAG 工程面试八股](../RAG面试八股.md) 的题号。
- 数字以 `application.yml` 运行时默认值为准；个别类内默认值与之不同（例如重排模型类内默认 `gte-rerank`、运行时默认 `gte-rerank-v2`）时，以运行时为准。
- 需求文档里写了、代码没有实现的内容，一律标注为偏差，集中登记在八股文末的「文档与代码偏差登记」。
