# 企业工作台 UI 实施与验收

## 设计依据与边界

2026-09-05 的设计审计覆盖 21 个路由、69 个页面及页面子组件，包含首页、知识资产、检索与问答、应用发布、评测、记忆、平台管理和身份入口。用户确认了交互设计稿后授权实现，要求保证工程功能质量。

默认 Atlas 采用浅灰侧栏、白色内容区与翡翠强调色。侧栏 228px、顶栏 64px、桌面内容间距 32px，页面主操作突出，批量操作仅在选择资源后出现。保留 Ocean、Violet、Cinder、Moss、Rose、Graphite、Night 及原有存储键、首屏主题和跨标签页同步。深色主题的强调文字与主按钮底色分别取色，保证文字可读性。

本次修改前端呈现及已复现的交互缺陷，不改变服务端 API、租户隔离、发布门禁、审核准入或鉴权规则。页面中的指标与状态全部来自现有接口；没有可用指标时展示明确的空态或错误态，不填充演示数字。

## 权限与调用归属

菜单依据 `visibleNavEntries` 过滤，页面按真实服务端权限细分动作，隐藏入口不能替代服务端鉴权。

| 场景 | 读取权限 | 写入或变更权限 |
| --- | --- | --- |
| 知识库 | `kb:read` | 配置/重建 `kb:write`；删除 `kb:delete` |
| 文档/分块/版本 | `kb:read` | 上传/编辑/重新处理/提交审核/版本激活 `doc:write` |
| 审核/有效期/可见性 | `kb:read` | `doc:review` |
| 回收站 | `doc:write` 或 `doc:review` | 恢复/彻底删除 `doc:review` |
| 数据来源/图谱 | `kb:read` | 来源写入和图谱抽取 `doc:write`；图谱开关 `kb:write` |
| 质量与反馈 | 反馈 `feedback:manage`；检索洞察另允许 `audit:read` | 沿用对应 API 权限 |
| 应用配置与版本 | `app:read` | 保存/提交测试/门禁集绑定 `app:write`；发布/回滚 `app:release` |
| 评测数据与对比 | `eval:read` | 采集须同时具备 `eval:write`；执行 `eval:run` |
| 用户与注册审核 | 用户 `user:manage` | 注册审核另须 `tenant:manage`，保留角色/租户分配校验 |

`MainLayout` 调用导航与快捷搜索；主题 Provider 同时驱动 Ant Design 和 CSS 变量。知识库详情负责编排当前页、抽屉与服务端刷新，`DocumentList` 负责响应式展现，`DocumentActions` 负责单个文档的可用动作。三种资源目录复用 `ResourceMenu`，用户列表和注册审核复用二级导航。

GitNexus 已分析被修改的现有页面与函数，页面与大部分函数返回 LOW，版本加载函数因 5 个直接调用方被评为 MEDIUM。文档加载函数有 15 个直接调用方，被评为 HIGH；已在修改前说明风险，并验证晚到响应不能覆盖当前页、勾选不跨页保留，以及上传、审核和批量回收后的刷新。JSX 引用的图谱覆盖有限，因此另外按路由和实际 API 调用逐项核对，不能把图谱的零调用结果理解为无影响。

## 回归策略

历史测试主要覆盖纯函数、主题和身份表单，未覆盖表格、折叠配置及真实浏览器键盘事件。本次先通过浏览器复现溢出、权限入口、重复表单初值、生成中回车重复提交和中文输入法误发送，再实施修复。新增验证包含：

- Vitest：原有全部用例和可取消 SSE 协议、断线与取消的区别。
- Playwright：独立启动当前工作区的 Vite，固定端口 20106 且禁止复用已有服务；所有 API 请求必须匹配显式夹具，漏配请求直接失败。
- 21 个路由分别检查 1440、880、390 三种宽度，检查页面溢出、异常和截图。
- 核心工作台使用 axe 验证 WCAG A/AA；验证实际 DOM，保留组件交互与焦点语义。
- 业务交互验证原有提交载荷、只读权限、危险操作确认和异步状态，不能用静态截图替代。
- 服务端、Python 解析、Java 解析及部署契约执行仓库 CI 对应命令。没有运行真实第三方模型或生产数据库写入；浏览器业务接口使用与服务端契约对应的测试夹具。

```bash

npm ci

npm run lint
npm run build
npx playwright install --with-deps chromium
npm run test:e2e

# macOS 可使用本机 Chrome，仍由 Playwright 启动专用测试服务
PLAYWRIGHT_CHROME=1 npm run test:e2e
```

所有验证结果以本 PR 的 CI 和验收报告为准。截图包含测试夹具数据，不作为生产业务指标。

## 已确认的交互根因

- 折叠和条件渲染：表单校验返回已注册字段，未挂载的路由提示词会遗漏。配置保存先校验，再读取完整表单存储；通过原配置逐字段对比验证。
- 表单清理：单字段 `setFieldValue` 触发 rc-field-form 元信息比较的共享空数组警告。保存成功后用字段级 `resetFields` 清理变更说明，保留完整表单校验。相关上游问题见 [rc-field-form #649](https://github.com/react-component/field-form/issues/649)。
- 减少动态效果：全局为所有元素指定 0.01ms transition-duration 会隐式启用默认的 all 过渡，干扰浮层将位置置零后立即测量的过程，产生整段视口外偏移。改为禁用过渡，并同步 Ant Design 的 motion token；用真实点击验证选择框、更多菜单和确认浮层。
- SSE 生命周期：同步请求引用阻止同一轮重复发送；中文组合输入不提交；停止或切换会话时中止请求并递增序号，旧回调无法写入新会话。
- 文档分页：旧页轮询可能晚于翻页响应返回。请求序号限制只有最新响应可以更新列表，目标页引用在请求发起时同步，后续轮询始终跟随当前操作意图。
- 门禁解绑：可清空选择器同时触发 `onChange` 和 `onClear`，原先两个事件都提交解绑。统一由 `onChange` 提交，回归断言实际请求只有一次。
