# RAG 技术导论：检索增强生成与企业知识库

## 为什么需要检索增强生成

大语言模型在通用语言能力上表现优异，但存在两个天然短板：知识截止于训练数据的某个时间点，
以及面对模型未见过的私有资料时容易产生"一本正经地编造"的幻觉回答。检索增强生成（Retrieval
Augmented Generation，简称 RAG）的核心思路很朴素：在模型生成答案之前，先从一个可控、可更新
的知识库中检索出与问题相关的原文片段，把这些片段连同问题一起交给模型，让模型"照着资料回答"
而不是"凭记忆回答"。这样一来，知识的更新只需要更新知识库，不需要重新训练模型；模型的回答也
可以附带引用来源，便于人工核实。

## 一条典型的索引与检索链路

企业知识库要把原始文档变成可检索的知识，通常要经过解析、清洗、切分、嵌入、双写、检索、重排
这几个阶段。解析阶段把 PDF、Word、Excel、图片等各种格式统一转换成文本加图片的中间表示；清洗
阶段去掉页眉页脚、水印、乱码等噪声，并按需做隐私脱敏；切分阶段按长度、标题层级或语义边界把长
文本拆成大小适中的分片，分片太长会稀释相关性，太短又会丢失上下文；嵌入阶段把每个分片转换成向
量，写入向量库的同时也写入一份全文索引，两路检索各有所长——向量检索擅长语义相近但字面不同的
表达，全文检索擅长专有名词和精确匹配；检索时把两路结果融合、再用重排模型精细打分，最后把最相
关的片段连同来源信息交给大模型生成最终答案。

## 评测驱动的持续优化

光把链路跑通并不代表效果好，切分策略、检索参数、模型选型的每一次调整都可能是"改好了"也可能是
"改坏了"。可靠的做法是维护一个标注过证据片段的评测集，每次调参后用同一批问题跑一遍检索，对比
命中率、排序质量等指标的变化，用数据而不是直觉决定是否发布。这种标注、评测、发布三位一体的闭
环，是企业级知识库区别于简单检索 Demo 的关键所在。
