# 知识质量问题处理

质量页增加独立问题记录，让 BAD 反馈和零命中信号经过领取、人工纠正、实际回归后再确认解决。原检索反馈仍保留 NEW/CONVERTED/DISMISSED 语义，BAD 分片不能直接转成正确证据。

## 使用流程

1. 在知识库的“质量与反馈”中，从 BAD 反馈或零命中统计点击“处理问题”。同一来源复用原问题。
2. 领取问题，填写原因、完整问题、标准答案及正确证据，选择当前知识库的评测集和受影响应用版本。正常回答必须有标准答案和证据；无依据拒答允许空证据。
3. 保存纠正用例后进入“待回归”。已有用例继续修订原记录，并校验问题与用例两个修订号。
4. 通过“打开评测任务”进入关联评测集，执行包含纠正用例的最终答案评测。
5. 回到问题页，选择已完成运行，对照标准、实际答案和五项评分，填写人工核验说明后确认解决。
6. 可以追加处理说明、释放给其他人，或说明原因后重新打开已解决问题。历史记录保留。

网页不会自动重试写入。冲突或响应丢失后，先确认服务端状态；载入最新内容时会提示放弃未保存草稿。返回页面重新检查权限，资料撤权后清除详情和草稿。关闭详情后焦点回到入口。

## 职责和授权

| 层 | 职责 |
| --- | --- |
| HTTP 入口 | `feedback:manage`、输入形状与长度、无缓存响应 |
| `QualityIssueAccess` | 显式租户 SQL、知识库范围、当前文档 ACL、应用范围、锁定关联用例 |
| `KnowledgeQualityIssue` | 负责人、阶段、修订号和状态变化 |
| `KnowledgeQualityIssueService` | 真实来源、事务、复用用例服务、处理记录 |
| `QualityRegressionVerifier` | 当前用例与冻结输入、配置、语料、证据和实际结果核验 |

所有入口先按当前租户和知识库授权。平台管理角色也不能绕过显式租户条件。纠正操作同时要求 `eval:write`、`eval:read`、`app:read`；核验与解决要求后两项。已有纠正内容的读取也受评测和应用权限约束。

原反馈文档、历次纠正文档、采用回归结果时的全部召回文档，都进入历史内容的授权范围。任一资料撤权时，列表只保留处理状态，详情与历史说明不可访问。预览只返回关联用例结果，不返回整批评测中的其他问题。

零命中入口传随机 `insight_id`，查询哈希只在服务器内部去重。摘要复用现有脱敏逻辑，不扩大原始问题日志。员工私有会话反馈尚未直接接入此知识库处理入口，多知识库和会话隐私边界需单独实现。

## 解决条件

解决操作在同一事务重新核验，不能仅依赖前端预览成功或运行的 SUCCESS 状态：

- 必须是保留 `case_inputs` 的成功答案评测；旧运行和纯检索运行不能用于解决。
- 人工确认的用例输入、评测冻结输入、当前 ACTIVE 用例必须相同。JSON 内容按语义比较，兼容 MySQL JSON 键顺序变化。
- 验证版本属于同一受影响应用，当前配置与运行快照相同，当前知识库语料指纹相同。
- 正确证据仍可检索、已索引，当前文档版本与标注版本相同；实际召回资料全部可读。
- 当前用例有有效生成答案、正确的回答或拒答行为、没有降级，正确性、忠实性、完整性、引用正确性、引用完整性分别达到 4/5。
- 正常回答的标准证据全部命中，人工确认说明非空。

此条件证明所选纠正用例满足当前核验规则。它不等于整个业务知识库、所有线上应用查询或真实用户问题都已通过质量验收；评测仍使用现有检索和答案评测机制。

## 回归依据的删除保护

被质量问题关联的用例和评测集不能单独删除，已解决问题的历史关联也受保护。删除入口把引用条件和读取时的修订号放在同一条写入语句中；评测集先取得删除资格，再在同一事务内级联清理用例和报告。引用存在或版本变化时返回 `EVAL_DATASET_CONFLICT`，任何内容都不会被部分删除。

没有质量问题引用的资源仍沿用原软删除行为。此保护针对评测资源的独立删除；知识库整体删除遵循原有知识库生命周期，问题内容也随知识库授权根失效而不可访问。

## 迁移和验证

V31 只新增 `t_kb_quality_issue`、`t_kb_quality_issue_record`，没有改写旧反馈或评测记录。V32 在问题表新增 `(dataset_id, deleted)` 和 `(case_id, deleted)` 索引，为删除引用校验提供查找路径，不改变已有内容。来源唯一键防止重复建单，所有处理写入使用乐观锁，问题、用例、集合修订号及记录在同一事务提交。

- `QualityIssueTransactionTest` 使用生产 Mapper、乐观锁和 Spring 事务，覆盖并发领取、重复来源、租户根、用例外部修改、冲突回滚、处理时间，以及关联用例和集合删除保护、过期删除与纠正并发时的报告保留。
- `QualityIssueMigrationTest` 仅接受独立 `codex_quality_migration_*` MySQL 测试库，验证完整 V1–V30 后升级 V31、旧输入保留、旧列写入兼容和唯一键；不会清理业务库。
- `QualityReferenceMigrationTest` 在独立 MySQL 库从 V31 升级，验证两个索引的字段与顺序、既有问题及处理记录保留、旧列写入兼容和重复迁移。
- HTTP 契约覆盖权限、参数、409、no-store 和响应字段投影；回归与资料授权测试覆盖过期输入、配置、语料、版本、评分和撤权。
- 浏览器使用严格合成接口夹具覆盖操作、草稿、冲突、网络结果不明、深链以及八套主题和五种宽度。合成测试不代替业务语料和真实模型验收。

迁移验证不等于旧二进制实际回滚验证。回滚部署前应保留数据库备份；本迁移可保留新增表，不要求破坏性删除。
