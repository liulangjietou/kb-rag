# 批量上传结果与失败恢复

知识库的“添加文档”抽屉会保留本次操作中每个文件的结果，并显示已接收、失败或未确认、等待与上传中的数量。

- “仅重试失败文件”只重新发送失败或结果未确认的文件；已接收文件保留结果。
- 每个失败文件也可以单独重试或从本次清单移除。
- 关闭并重新打开抽屉可继续核对结果；刷新、离开当前知识库或切换账号后，清单会结束。
- 服务端判定内容重复时，显示已有版本和“未重复建版”；“已接收”之后的解析、索引和审核状态继续在文档列表查看。
- 网络中断可能发生在服务端接收之后。此时先核对文档列表，再决定是否重试；服务端沿用现有内容去重规则。

## 工程边界

文件队列属于当前会话、授权范围和知识库。每次最多发送两个请求，同名文件串行发送以保留选取的版本顺序。已接收文件释放浏览器中的文件引用；页面范围变化后，尚未发送的文件停止排队，迟到响应不能刷新另一个知识库。已经发出的请求可能仍在服务端完成。

API 仍使用既有的 multipart 文档上传接口。服务端负责文件大小、格式、权限、知识库边界和内容去重校验。队列只在当前页面内存中保留，不增加数据库表或任务调度平台。

## 验收要点

1. 同一批次一个成功、一个失败：关闭重开后仍可核对，点击批量重试只产生失败文件的第二次请求。
2. 相同内容重试：显示服务端的重复内容结果，不能表述为已经索引或发布。
3. 四个文件含两个同名文件：最多两路并发，同名文件顺序执行。
4. 请求未完成时切换知识库或身份范围：未启动文件不再发送，旧响应不污染新页面。
5. 只读角色没有上传入口；390/768/1440px 下长文件名可换行，失败重试可键盘操作，Esc 关闭后焦点回到入口。

来源同步的失败对象重试和索引任务恢复属于独立链路，不由这个浏览器上传清单代替。
