# 员工知识问答界面

## 使用入口与部署依赖

员工入口为 `/workspace`，需要 `app:use` 权限和已分配的应用范围。应用必须有正式发布版本，用户还需有应用所引用知识库的当前访问权限。该入口复用控制台登录，默认首页仍为 `/home`；应用管理和调试入口继续使用原有权限。

部署前应完成 V27、V28 迁移并启用 [员工运行服务](EMPLOYEE-RUN-RUNTIME.md)。前后端必须一起发布员工接口和页面；仅发布页面会显示读取失败，不会转用管理接口绕开权限。会话表和回退规则见 [会话账本](EMPLOYEE-CONVERSATION-LEDGER.md)。

## 前端职责

`EmployeeWorkspacePage` 管应用目录、会话列表和地址导航。`ConversationView` 管输入、阅读、引用和重命名/删除操作。`useEmployeeConversation` 管一个会话的读取、提交、停止和状态合并。`employeeWorkspace.ts` 负责 HTTP 契约与一次只读 SSE 连接，不负责自动提交模型任务。

- 地址保存 `app` 和 `conversation` 标识，正文、问题、引用和令牌均不写入地址。
- 会话列表按标题或用户问题在服务器分页搜索；回答内容不作为会话搜索词来源。历史每页最多 20 轮，使用排他的 `before_turn` 游标。
- 用户提问创建随机 `request_id`。发送结果不明时保留草稿和原请求，显式“确认发送结果”重用同一个 ID；自动恢复只 GET 已有运行。用户选择“重新生成”才创建新的请求 ID。
- 两个标签同时提交时，冲突页显示服务端忙碌状态，读取当前运行并保留未发送草稿。
- 导航、刷新和关闭标签仅释放读取资源。明确停止使用单独的停止接口；界面只展示该接口返回的已保存结果。删除前说明会移除会话并停止仍在执行的回答。
- 旧检查点不能覆盖新回答，终态不能被迟到的活动状态恢复。摘要与运行列表一起合并，读取期间新接受的问题不会被旧空列表抹掉。

## 连接、权限和隐私

连接失败按 1、2、4、8、16 秒退避，连续失败后显示手动重连入口。超过 10 秒的有效连接重置退避次数。服务端每次订阅最长 120 秒，客户端预留传输时间后以 135 秒为硬期限，防止失联连接无限等待；这个期限只取消读取，不停止后台运行。

页面可见时每 15 秒重读一次当前摘要与历史，重新获得焦点时重新核验；隐藏页面覆盖正文，重新可见后等待当前授权结果。打开引用也会重新核验。权限错误立即清除内容，旧订阅快照及撤权前发起的读取不能重新启用正文；必须发起新的有效授权读取。单条历史回答被标记为受限时，本次视图不自动恢复其旧内容，重新打开会话会取得新的授权投影。

接口使用 `no-store`，没有把会话内容持久化到浏览器存储。Markdown 不执行原始 HTML，不加载模型提供的远程图片；外链仅接受 HTTP、HTTPS、mailto，并使用新窗口及 `noopener noreferrer`。表格和代码可以键盘滚动，复制失败会给出明确反馈。

当前轮的 `[1]`、`[2]` 按模型实际使用的检索来源顺序展示。历史依赖显示“上下文来源”，不冒充当前编号。引用阅读器展示保存时的具体文档版本、真实物理页码或切片序号及引用片段，不将逻辑分段伪装成 PDF 页码。

## 交互验证

已有风险测试覆盖异步响应顺序、撤权与旧回调并发、黑洞连接超时、安全 Markdown、引用边界与复制失败。浏览器测试使用明确 API 夹具，覆盖最小使用权限、无权限、空目录、列表失败、输入法回车、换行、发送结果确认、显式停止、两标签冲突、切页和刷新恢复、历史分页、长文滚动、引用撤权以及迟到的新建响应。

布局验证覆盖八套主题与 390、768、1280、1440、1920 五种宽度，并对页面执行 WCAG 2/2.1 AA 自动检查。抽屉关闭后焦点返回触发按钮，输入区保持可见。窄屏以正文为主，历史和来源分别打开抽屉；桌面同时展示历史、问答和依据。

运行验证：

```bash
cd kb-rag-web
npm ci
npm run test
npm run lint
npm run build
npm run test:e2e
```

浏览器夹具验证交互契约，不代表真实模型质量或性能。固定语料 RAG、实际模型首字与总时延、杀进程后恢复仍需单独验收。员工反馈入口、负面反馈回归闭环与来源运营待办属于后续批次，不包含在本次页面交付中。
