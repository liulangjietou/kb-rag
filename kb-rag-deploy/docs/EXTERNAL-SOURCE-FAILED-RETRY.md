# 外部来源失败项重试

知识库的“外部数据源 → 查看对象”默认筛选失败对象，直接显示失败原因与最近处理时间。
具有文档写权限的用户可以选择“仅重试失败项”，只读用户保留查看、筛选和刷新能力。

## 操作与结果

1. 根据对象明细的原因修复连接或来源配置。
2. 提交失败项重试，后台复用该来源的连接器和普通文档入库流程。
3. 刷新明细查看逐项结果；取消“仅看失败对象”可查看已经恢复的对象。

受理响应不是完成结果。关闭页面不取消已提交的处理；网络异常时先刷新核对，避免连续提交。
重试不扫描接入新对象，也不重新处理健康对象；“最近完整成功”与来源的完整同步状态由“立即同步”更新。
重试带来新版本时，内容变更时间独立推进，文档的解析、审核与索引状态仍以文档页面为准。

## 范围与恢复

- 每批重试最多处理 `kb.ext-source.max-objects-per-source` 个失败对象，优先处理最久未尝试的记录。
- 复用有上限的远端清单以取得实际对象版本和标题。清单截断时，未出现的对象保持失败并记录范围提示；只有完整清单才能证明对象消失。
- 对象已消失或类型不再受支持时标为跳过，不删除绑定文档；回收站文档沿用原有保护规则。
- 失败状态不能仅凭相同 ETag 标为未变化。重新入库成功后，数据库中的旧失败原因会清除。
- 单实例内同一来源的完整同步和失败重试互斥；已有操作执行时，后续重叠操作不会重复写入。
- 执行中断后，已经落库的逐项结果保留，尚未完成的失败对象仍可人工重试。此入口不提供后台队列接管或自动续跑承诺；遵守现有单实例调度边界。

## 接口

- `POST /api/v1/ext-sources/{sourceId}/retry-failed`：文档写权限与知识库范围验证后返回 `{accepted:true}`。
- `GET /api/v1/ext-sources/{sourceId}/items?failed_only=true`：失败筛选在数据库分页前完成。不传参数维持原有全部对象查询。

本批无数据库迁移，不新增持久枚举值，保留旧版本读取同一数据表的兼容性。
