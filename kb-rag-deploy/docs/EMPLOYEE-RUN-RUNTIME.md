# 员工问答运行与连接恢复

员工问答通过独立 HTTP 命令接受问题，通过 GET/SSE 读取同一个持久运行。浏览器关闭、导航和连接失败只影响订阅；明确停止才取消问答。底层复用正式检索、生成和有界聊天执行器，部署仍采用 [单实例后台执行基线](DURABLE-SCHEDULING-DECISION.md)。

## 接口与授权

所有路由都要求控制台 `satoken` 以及 `app:use`，每次内容读取重新解析当前身份。会话归属固定为租户、用户和应用三元组；应用管理权不能替代使用权。下表以 `/api/v1/workspace/apps/{appId}/conversations` 为前缀。

| 方法与后缀 | 行为 |
| --- | --- |
| `GET /` | 按标题及本人原问题搜索、分页；不搜索可能已撤权的答案 |
| `POST /` | 以 `{ "title": "报销制度" }` 创建空会话，不调用模型 |
| `GET /{conversationId}` | 返回会话摘要与 `active_run_id`，支持两个标签页恢复同一活动运行 |
| `PATCH /{conversationId}` | 修改标题；不以客户端旧摘要覆盖活动状态 |
| `DELETE /{conversationId}` | 在同一事务内取消活动运行并软删除会话，提交后取消上游 |
| `GET /{conversationId}/runs` | 轮次倒序历史；`before_turn` 为不包含的游标，`limit` 最大 50 |
| `POST /{conversationId}/runs` | 接受问题，首次接受才在事务提交后调度 |
| `GET /{conversationId}/runs/{runId}` | 读取当前已提交的安全快照，不启动执行 |
| `POST /{conversationId}/runs/{runId}/stop` | 先保存停止，再取消上游；对终态调用保持其原状态 |
| `GET /{conversationId}/runs/{runId}/events` | 只读 SSE 订阅；重连继续读取相同运行 |

提交请求示例：

```json
{"request_id":"c61b53ae-1cf8-441a-b027-e8aa4d2b26d2","query":"报销时需要哪些材料？"}
```

网络重试必须保留同一个 `request_id` 和完整原问题。服务端先在会话锁内检查幂等，再解析当前发布版本；原请求重放不受后续换版或暂时无发布版本影响。同一标识换内容返回 `409 CONVERSATION_REQUEST_CONFLICT`；另一个运行尚未结束时返回 `409 CONVERSATION_BUSY`。用户明确点击重新生成时使用新标识，形成新运行与新轮次。

请求标识为 8–128 位字母、数字、下划线或连字符，问题最多 8,000 个 Java 字符，标题最多 120 个字符且不能全为空白。历史、引用、执行配置、模型和版本均由服务端产生，客户端不能通过请求覆盖。

## 持久化与执行

1. 账本在短事务中保存原问题、正式应用版本及其读取语义，并占据活动位置。
2. 有界执行器领取运行。只有 `start` 成功才能执行，队列拒绝保存失败终态并释放会话。
3. 当前可读的成功历史进入上下文，其来源依赖与本轮证据合并。生成开始前先保存引用。
4. 每秒维护一次累计正文检查点或心跳，并重验身份、应用范围及全部证据权限。
5. 完整答案、成功终态和活动位置释放在同一事务提交。连接只能读取提交后的状态，不能凭内存完成信号发送成功。

权限撤回或维护失败会立即取消生成并尝试保存失败，即使上游仍处于阻塞中，也不继续心跳维持活动状态。保存部分正文失败后仍尝试终态事务；数据库持续不可用时停止维护，留待过期补偿。终态不可逆，迟到的检查点、失败和成功回调不能复活运行。

一次运行上限为 10 分钟、100,000 个 Java 字符的回答。正常关闭将本实例持有的排队/执行运行标为 `INTERRUPTED`。应用初始化完成后每 30 秒扫描一次三分钟未更新的活动运行，每批最多 100 条；取得会话锁后重验更新时间再中断，不自动重新生成。

明确停止可以取消生成阶段的上游 HTTP 请求。检索管线在进入和退出时检查取消信号；其内部尚未接受取消信号的同步改写、重排请求可能继续到自身超时，但不会再进入后续生成。这一边界不能描述为所有检索 HTTP 都能即时中止。

## SSE 客户端约定

订阅每秒读取一次持久快照，空闲五秒发送一次注释心跳。每条连接最长两分钟；实例最多 64 个连接、同一租户用户最多四个。超额返回 `429`，连接完成、超时、断线和应用关闭都会回收定时任务。

| 事件 | 数据与客户端处理 |
| --- | --- |
| `snapshot` | 完整 `EmployeeRun`；替换相同运行的状态，不追加整段正文。事件 id 为 `run_id:revision` |
| `done` | `{run_id,status,revision}`，只有读到持久终态后发送。`FAILED/CANCELLED/INTERRUPTED` 也属于终态，不能都渲染成成功 |
| `error` | `{code,message,retryable,clear_content}`，只说明订阅失败；不能自动重新提交问题 |
| 注释 `keep-alive` | 仅保持连接，不更新模型进度 |

重新订阅总会发出当前完整快照，不依赖保存原始 token 事件。客户端保持 `run_id`；只对 GET/订阅做有上限的退避重连，不能自动生成新的请求标识。收到终态或用户导航离开时释放旧 reader、计时器和连接。

`restricted` 可能在持久 `revision` 不变时改变，所以相同序号的权限投影仍需应用。`restricted=true` 时清空该回答与引用；`clear_content=true` 表示当前会话/身份已不可访问，应清除相应界面缓存。历史回答也必须经服务器当前权限校验，不能只靠本地已保存的正文恢复。

HTTP 与 SSE 共用同一响应 DTO，只包含可展示字段。`snapshot_bound` 区分正式冻结快照与历史版本使用当前语料；`page_no` 仅为实际 PDF 页码，`chunk_title` 与 `chunk_ordinal` 不冒充原文标题或段落号。

引用数组先保留本轮检索的原始顺序及数量，正文 `[1]` 对应第一个本轮条目；即使条目重复也不能压缩后让后续编号错位。历史独有依赖追加在后并标记 `inherited=true`，仅用于说明上下文来源与权限重验，不分配本轮引用编号。

## 验证、部署与回退

- 运行协调测试覆盖只调度一次、上下文绑定、证据保存顺序、取消顺序、部分答案、队列拒绝、撤权、停机和过期扫描。
- 会话账本的 18 项测试在 H2 和独立 MySQL 8.0.36 库验证，覆盖并发、事务回滚及显式归属。
- MVC 契约测试覆盖所有路由权限、分页与输入限制、安全字段和请求幂等参数。
- SSE 测试覆盖同序号撤权、错误与终态区分、连接上限和资源回收。
- 嵌入式 Tomcat、真实 TCP、真实事务 Mapper 与执行线程的集成测试验证：强制 TCP RST 后运行继续，重连读取同一答案；停止先提交再取消上游；终态事务被故障约束拒绝时不报告成功。

运行集成测试的身份解析与检索模型为可控夹具；其结果不替代真实模型质量评测或员工页面验收。执行 JDK 17 `mvn verify -DexcludedGroups=browser` 可运行上述服务端验证。

部署前完成 V27/V28。本批不新增数据库迁移。回退到仅含账本的版本会失去 HTTP/执行入口，必须保留已有会话表；重新部署时过期补偿会中断遗留活动运行，不自动重跑。不要删除会话数据作为代码回退手段。
