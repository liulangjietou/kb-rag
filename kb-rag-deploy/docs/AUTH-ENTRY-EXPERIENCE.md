# 登录与注册入口体验

登录、注册资料页在 1280×720 桌面视口内显示主要提交按钮。紧凑外壳只由这两个页面启用；改密和无权限页保留原有布局。知识接入、有据可查、质量改进三步展示产品用途，账号、密码、验证码和主操作集中在同一卡片内。较短视口和移动设备允许正常纵向滚动，不裁剪表单或错误提示。

## 身份方式与凭据

- 平台账号始终可用；目录方式根据服务端 `sso_available` 显示。没有成功记录时保留原有选择规则：未填凭据且没有缓存的平台用户名时，配置允许可默认选择目录。
- `kb-rag.login-method.v1` 只保存上次认证成功的 `LOCAL` 或 `SSO`，不包含用户身份或凭据。配置已禁用目录时回到平台账号；失败或仅切换标签不更新成功记录。关闭用户名记忆会清除原有用户名缓存，方式偏好仍可保留。
- OIDC、SAML、CAS 入口只在各自配置开启后出现，使用原有整页跳转协议；本次不自动重定向到企业身份提供方，也不推断哪个浏览器 SSO 协议上次成功。
- 目录和单点登录配置可能晚于浏览器自动填充返回。配置重绘前把原生表单中变化的值同步到受控字段；已经开始输入、自动填充或提交后，不再自动切换方式。两个配置响应同批到达时，不将切换前的 DOM 字段写回新方式。
- 切换账号方式会清空密码、刷新一次性验证码，并在当前页面保留各方式的用户名输入。勾选记住不会把密码写进站点存储；只有认证成功后，才按用户当时的选择调用浏览器密码管理器。请求中撤回选择继续生效。

## 安全与交互边界

拼图仍使用服务端图片比例和原有拖动、轨迹、键盘、一次性 proof 以及验证后提交逻辑。只限制登录页拼图展示宽度，不隐藏图片或调整后端安全规则；滑块触控尺寸维持 46px。移动端输入、提交与企业单点登录按钮至少 44px。刷新拼图文字使用主题文本色，保证深色主题可辨认。

注册仍先验证邮箱取得短期 ticket，再提交账户资料等待管理员审核。紧凑样式不改变 ticket 有效期、密码强度、幂等提交、敏感信息存储或审核规则；上一步仍保留邮箱输入。服务端、数据库和 API 契约均未改动。

## 验证与回滚

现有布局用例只有 1000px 高度，未覆盖 720px；新增真实浏览器断言先复现登录和注册提交按钮离开首屏，再验证修复。登录方式与原生自动填充使用单元和浏览器延迟响应测试，覆盖配置晚到、同批响应、目录停用、用户切换和保存授权撤回。

登录和注册两步覆盖 390、768、1280、1440、1920 五种宽度和八套主题，检查横向溢出、桌面主要提交区域、移动目标尺寸、返回行为及截图。八套主题的桌面入口和深色移动入口执行 WCAG 2 A/AA、2.1 AA 自动检查；完整既有 Web 单元、E2E、静态检查和构建作为交付门槛。测试接口使用明确夹具，不向真实邮箱发信，也不代替真实身份提供方登录验收。

回滚可独立还原本次前端提交，无数据库或服务端迁移。旧前端忽略新增的方式偏好键；该键不影响认证结果，不需要清理真实账号数据。
