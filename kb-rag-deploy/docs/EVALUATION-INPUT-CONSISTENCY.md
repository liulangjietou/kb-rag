# 评测输入一致性

用例新增、修改、删除和证据复核，与集合修订号及计数一起提交。MyBatis 乐观锁未命中时只返回零行；服务显式检查该结果，返回 `409 EVAL_DATASET_CONFLICT` 并回滚整个事务。删除也携带读取时的用例版本，防止按旧状态删除后来已被修改的用例、错误调整计数。用户重新读取最新内容后再提交；服务不自动重试覆盖他人的修改。

提交普通检索评测或最终答案评测时，服务通过独立的 MySQL `REPEATABLE_READ` 只读事务，一次读取同一数据库视图下的集合修订号与用例输入。事务在模型调用前结束。同批配置共用这份输入；运行的 `case_inputs` 保留问题、多轮上文、标准答案、拒答期望、证据、锚点类型和当时的用例状态，不复制运营备注。

排队后编辑或废弃用例不会改变已提交运行的输入。执行器从已保存的输入恢复原有用例执行器需要的对象，不重新读取当前用例表，也不回写已废弃的用例。旧的已完成运行保持原记录；缺少输入快照的旧待执行运行明确失败并要求重新提交，不把现在的用例内容附会为历史输入。

运行列表和详情仍使用原有最小响应 DTO，不返回 `case_inputs` 中的原始问题、标准答案与证据。输入快照只证明本次评测使用的用例内容；它不等于冻结检索索引，也不能单独证明问题已解决。运营闭环还需要核对受影响应用版本、实际回归结果、证据与人工判断。

部署先执行 V30，再更新服务。V30 只增加一个可空列；已有运行不补写推测快照。回滚服务时保留该列与历史输入，不删除数据。迁移和旧列写入兼容性在隔离 MySQL 验证；旧二进制进程回滚需另行演练。

`EvalDatasetConcurrencyTest` 在 H2 执行通用写入、回滚和不可变输入检查。跨表快照并发断言只在实际 MySQL 执行，因为 H2 的 `REPEATABLE_READ` 可读到另一个表中新插入的行。设置 `KB_EVAL_TEST_JDBC_URL`、`KB_EVAL_TEST_USER`、`KB_EVAL_TEST_PASSWORD` 后运行该类；JDBC 数据库名必须以 `codex_eval_consistency_` 开头，使用独立临时库，测试结束后删除该库。
