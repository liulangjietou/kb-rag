# 登录滑块验证码契约

## 1. 适用范围

登录页内的 `LOCAL` 平台账号和 `SSO` 目录账号共用本契约。OIDC、SAML、CAS 浏览器重定向登录继续由身份提供方完成认证，不重复叠加本站滑块。

滑块验证码是登录口令校验前的一道低成本自动化门槛，不替代账号锁定、BCrypt、目录认证、网关限流或 WAF。公开部署仍应在入口层配置限流与异常流量治理。

## 2. 一次性准入流程

```text
POST /api/v1/auth/captcha/challenge
  -> 服务端随机生成带缺口背景与透明拼图片，不返回横向答案
  -> 浏览器展示拼图并采集一次滑动轨迹
POST /api/v1/auth/captcha/verify
  -> 服务端校验随机落点、实测耗时与轨迹并签发短时一次性 proof
POST /api/v1/auth/login (携带 captcha_proof)
  -> 原子消费 proof
  -> 校验账号密码或目录凭据
  -> 签发登录 token
```

- challenge、proof 都由 32 字节高熵随机数生成，并放在有容量上限和 TTL 的进程内缓存中；服务端只保存它们的 SHA-256 摘要。
- 每个 challenge 都生成固定尺寸的随机 PNG 背景与透明拼图片。横向目标只保存在服务端，响应仅包含图片、尺寸和纵向展示位置；客户端自报时间只作轨迹信号，签发 proof 前还必须满足服务端单调时钟实测的最短耗时。
- challenge、proof、口令登录和浏览器 SSO 审计共用统一解析的客户端地址。只有 socket peer 命中 `TRUSTED_PROXY_CIDRS` 时才读取 `X-Forwarded-For`，并从右向左剥离可信代理；直连或未列入白名单的来源无法用转发头改写地址。默认只信任官方本地 Vite 使用的 loopback，生产必须替换为实际网关 CIDR，禁止配置 `/0`。服务固定 `server.forward-headers-strategy=none`，并在启动时拒绝 Boot/Tomcat 提前处理转发头，确保应用白名单始终是第一信任边界。
- `verify` 与 `login` 请求在 Jackson 反序列化前分别有 32KB、8KB 实际字节硬上限，同时覆盖矩阵参数路径、错误或缺失的 `Content-Length`、chunked 和 HTTP/2 请求体；字段层再限制用户名 128、密码 512、mode 16 和固定 43 字符 proof。
- 可识别并进入应用校验的 challenge 会在拼图、轨迹、绑定或限流判断前原子消费；可解析出 `challenge_id` 但缺少轨迹或轨迹点字段的请求也会消费 challenge。通过请求字段校验的登录会在账号密码校验前原子消费 proof。账号密码失败、来源不匹配或限流后，重放同一值必须失败。无法解析的 JSON 或缺少 `challenge_id` 的请求会在进入应用服务前被拒绝，不声称消费其中的值。
- 验证码失败不进入 `t_kb_login_audit`，避免匿名请求被计入账号锁定；真实凭据失败仍沿用现有登录审计和锁定规则。
- 登录守卫在无事务状态下先按用户名和来源地址加锁，失败审计在独立事务提交，成功后才进入成功事务；锁在事务提交后释放，避免并发请求越过阈值或在等待锁时耗尽连接池。未知账号与错误登录入口也执行固定 dummy BCrypt 校验，降低本地账号时序枚举差异。
- challenge、proof、验证码限流与登录守卫都是进程内状态。多实例部署必须按客户端固定粘性路由，并在网关执行全局登录限流；若要求严格的全局验证码额度与失败阈值，则必须迁移到 Redis/数据库等共享原子存储。

## 3. 前端交互

- 用户填写账号和密码后，通过鼠标、触摸或键盘把拼图片移动到随机缺口；前端不自行判断答案，服务端返回 proof 后页面自动提交原生表单。
- 自动提交继续经过 `onSubmitCapture`，确保浏览器密码管理器自动填充但未触发 React `change` 的值也能同步到请求。
- 同一个 proof 只允许触发一个在途登录请求。账号、密码或登录模式错误时，页面保留输入、清除 proof、刷新 challenge，并提示重新验证。
- 共享请求拦截器负责展示后端错误，登录页不重复弹第二条相同消息。

## 4. “记住用户名和密码”边界

应用只在 `localStorage` 保存是否记住以及各登录模式的用户名，不保存密码。密码字段保持标准的 `autocomplete="current-password"`；用户勾选后，支持 Credential Management API 的浏览器可把成功登录的凭据交给浏览器或系统密码管理器保存。

不得把密码明文、Base64 或使用前端可取得密钥加密后写入 `localStorage`、`sessionStorage` 或 IndexedDB。这些做法在 XSS 威胁下都等价于明文持久化。

## 5. 错误语义

| 场景 | HTTP / 业务码 | 页面行为 |
| --- | --- | --- |
| challenge、拼图落点或轨迹无效、过期、绑定不匹配、proof 缺失或重放 | `400 / INVALID_PARAM` | 清除验证状态并获取新 challenge |
| verify 超过 32KB 或 login 超过 8KB | `413 / PAYLOAD_TOO_LARGE` | 保留输入并重新获取 challenge |
| 验证码接口调用过于频繁 | `429 / RATE_LIMITED` | 保留输入，等待后重试 |
| 账号或密码错误 | `401 / UNAUTHORIZED` | 展示既有认证错误，保留输入并重新滑动 |
| 登录成功 | `200 / OK` | 进入原目标页；强制改密账号进入改密页 |
