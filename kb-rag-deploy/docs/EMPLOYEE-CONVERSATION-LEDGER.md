# 员工会话持久化与证据边界

本批为员工正式问答提供可验证的服务端基础：持久账本、当前证据权限过滤、历史上下文及严格快照执行入口。后台调度、连接订阅、HTTP 会话接口和员工页面仍由后续批次接入；本批没有增加可直接调用的会话 HTTP 路由，也不代表已经支持浏览器恢复或完整员工问答。

## 数据与职责

- V28 新增 `t_kb_conversation` 与 `t_kb_conversation_run`。会话和运行均记录 `tenant_id + user_id + app_id`，内部后台访问也显式限定这三个字段；租户插件提供请求线程上的额外边界。
- `EmployeeConversationLedger` 只访问数据库。所有状态更新先锁定所属会话，模型调用与连接推送必须在短事务之外执行。
- 同一会话只允许一个活动运行；`conversation_id + client_request_id` 和 `conversation_id + turn_no` 具有唯一约束。相同请求标识和问题返回原运行，替换问题返回 `CONVERSATION_REQUEST_CONFLICT`，另一运行尚未结束时返回 `CONVERSATION_BUSY`。
- `accept` 提交原问题与捕获的执行配置之后才返回。只有 `AcceptedRun.created=true` 的调用方可以提交调度；执行者还必须取得 `start` 的一次性领取资格。刷新和重连不能调用这两个动作。
- 问题、归属、轮次和执行配置只在插入时写入，不随心跳或答案检查点重写。

## 状态与保存顺序

状态为 `PENDING → RUNNING → SUCCEEDED / FAILED / CANCELLED / INTERRUPTED`；排队拒绝也可由 `PENDING` 进入 `FAILED`，明确停止可终止尚未开始的运行。任何终态都不能被后续回调恢复为运行或成功。

生成前调用 `retrieved` 保存已经过滤的引用及实际读取语义；之后才能保存累计答案检查点。检查点序号只允许递增。`succeed` 将完整答案、成功终态和会话活动位置在同一事务内保存，调用方只能在其成功返回之后通知完成。数据库写入失败或释放活动位置失败会回滚该事务，不能发送成功事件。

`cancel` 先保存终态，上层再取消该运行的 `ChatCancellation`。账本不持有浏览器连接。`interruptIfStale` 在取得会话锁后重新检查更新时间，扫描后已有心跳的运行不会被误中断，也不会被自动重跑。补偿扫描与定时心跳的调度尚待接入；本批不提供跨实例自动接管。

## 授权与证据

`EmployeeWorkspaceAccess` 复用员工目录的当前身份校验，并提供会话所需的应用根、正式版本及知识库范围检查。后台再次解析身份时要求用户与租户仍匹配原请求；应用管理权不替代 `app:use`。历史读取需要当前应用使用范围和有效应用根，但不要求此时仍有发布版本。

引用使用检索返回的已裁剪正文，不能从原始 chunk 再读出被排除的片段。仅保存稳定文档、版本、片段标识与可核实的名称、时间和定位数据，不保存过期的预签 URL。物理页码目前仅接受 PDF 元数据；DOCX、表格、网页的逻辑分页不显示为物理页码。

`chunkTitle` 表示切片元数据中的片段标题，可能由语义切片生成；不能将它标为原文章节标题。`chunkOrdinal` 表示该版本中的片段顺序，也不等于原文自然段编号。

历史读取与模型上下文均重新检查知识库归属、当前文档 ACL、文档/版本是否存在，以及发布、生效、过期、回收状态。任一来源不可读时，整条回答及引用被遮蔽，不能只隐藏引用而继续展示其派生答案。用户自己输入的问题保留显示，但该问答对整体排除在模型历史之外。

历史上下文还携带其完整来源依赖，新回答需要保存这些继承依赖与本轮引用的并集。因此本轮没有新命中，也不会丢失其通过前文使用的资料。最多选取最近 10 轮、合计 24,000 字符的可读成功历史；不截断单个问答对形成误导性的半段上下文。

这里的过滤服务是内部边界，调用者必须先取得当前身份并校验会话归属。账本实体含问题、原始答案、引用及内部配置，禁止直接序列化为 HTTP 响应。

## 版本语义

`EmployeeRunTarget` 捕获接受时的应用版本、配置、冻结索引与可见文档版本集合。后续发布导致旧版本变为 `SUPERSEDED`，不会把已经接受的运行切换到当前语料。

`KnowledgeApiService.employeeStream` 复用既有检索和生成管线，并在生成之前调用证据持久化回调；它不发送 `done`，也不从当前应用版本重新解析运行目标。拥有快照的员工运行启用 `strictSnapshot`：

- 快照内版本集合为空时保持为空，检索服务不查询该库。
- 索引或版本集合绑定缺失时返回 `KNOWLEDGE_SNAPSHOT_UNAVAILABLE`，禁止静默读取当前语料。
- 从未保存过快照的历史发布仍明确采用当前语料，`snapshotBound=false`，界面接入时必须显示实际语义。

公开 API、MCP、调试和评测的默认行为保持原契约，严格模式仅由新的员工执行入口设置，浏览器请求不能任意指定它。

## 验证与部署

新增测试覆盖真实 Mapper 与 Spring 事务下的幂等提交、两个标签页竞争、终态竞争、回滚、归属隔离、心跳过期重验；相同 13 项账本测试在 H2 和 MySQL 8.0.36 的 `REPEATABLE READ` 隔离级别均通过。MySQL 使用随机独立 schema 和临时账号，测试结束后清理。

可选 MySQL 重跑设置 `KB_CONVERSATION_TEST_JDBC_URL`、`KB_CONVERSATION_TEST_USER`、`KB_CONVERSATION_TEST_PASSWORD`。数据库名必须以 `codex_conversation_` 开头，且必须专用于测试；测试只创建并移除本批两张表。凭据仅通过环境变量传入。

另有证据撤权、继承依赖、上下文顺序、时间边界、PDF 定位及严格快照测试，并回归原公开问答和快照回退契约。上述结果不代替实际模型 RAG 质量、页面流畅度、断线恢复或服务重启实验，这些需在后续接入完成后验证。

部署以 V27 为前置版本，Flyway 顺序执行 V28。该迁移只新增表，不修改既有业务数据。回退应用版本时保留两张表中的会话数据；尚未启用会话功能时也无需删除表。不要为代码回退执行 `DROP TABLE`，后续重新部署可以继续使用已有数据。
