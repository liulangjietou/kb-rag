# 文档筛选与状态同步

文档页提供文件名、处理状态、发布状态、来源和更新时间组合筛选。所有条件通过 `GET /api/v1/kb/{kbId}/documents` 在数据库分页前执行。提交或重置筛选返回第 1 页，翻页、上传与删除后的刷新保留已应用条件；勾选仅限当前页，切换条件或翻页会清空勾选。

## 数据与权限

- 权限仍为 `kb:read`，先由 `KbResourceGuard` 确认租户与知识库范围，应用层保留租户围栏。没有扩大受限文档的内容读取权限。
- 文件名关键词去除首尾空格后最多 200 字符；`%`、`_`、`!` 按字面检索，通过绑定参数传值。
- `PUBLISHED` 包含历史空发布状态，和文档响应的兼容语义一致。
- 来源通过同库网页登记、外部数据源条目与父数据源关联，以及聊天 `source_key` 识别。关联使用 `EXISTS` 避免一篇文档重复计数。已软删除的来源登记仍可证明历史来源；没有保留关联的旧文档归入“上传或未关联来源”，不推断具体渠道。
- `updated_from` / `updated_to` 为服务端 ISO 本地时间，包含起止边界。界面选取整天，结束日期到 `23:59:59.999`；上界早于下界、非法状态和非法时间返回 `400 INVALID_PARAM`。
- `DocumentResponse.updated_at` 直接来自文档记录；它表示记录更新时间，可能由内容、处理或治理操作改变，不表示内容版本发布时间。旧服务端缺少此字段时显示“暂未提供”。

## 状态同步

`GET /api/v1/kb/{kbId}/rebuild-status` 保留原三个追平计数，增加全库 `document_count` 和 `processing_count`，不受列表筛选与分页影响。全部排除逻辑删除与回收站文档；配置追平仍要求存在活跃版本。`processing_count` 包含 UPLOADED、PARSING、PARSED、INDEXING，不包括等待人工确认。

可见文档标签有活跃处理时每 3 秒同步，空闲每 30 秒；前一轮完成后才安排下一轮，连续失败按指数退避，上限 60 秒。隐藏页面或离开文档标签暂停，回到可见文档标签立即同步。用户手动刷新仍可立即执行。旧页、旧筛选、旧知识库的慢响应不能覆盖当前结果。

文档列表和进度失败分别展示错误与重试，不解释为零值。检索洞察的统计与列表也分别区分加载中、失败、真实空结果，并显示成功更新时间。列表重试保留查询条件。

原界面用当前页查询总数计算整库重建百分比，筛选后分母不再可靠；现在显示服务端实际的待追平、处理中、排队中和失败数量。自动重建与状态统计共用未回收文档范围，避免继续处理已移入回收站的文档。

## 部署与回滚

没有数据库结构迁移。先发布服务端，再发布前端。旧客户端可以忽略新增响应字段；旧服务端不支持新筛选语义，因此不要先发布筛选界面。回滚前端可保留新版服务端；整体回滚时先回滚前端，再回滚服务端。源数据与文档状态不需要回滚。

验证包括真实 MyBatis + H2 MySQL 模式查询、MVC 权限与参数绑定、浏览器筛选分页与失败恢复、中文输入、响应式布局、慢响应覆盖、隐藏暂停和失败退避。H2 验证不等同于大数据量 MySQL 性能验收；上线前对生产同等规模数据检查文件名模糊检索和来源关联查询计划。
